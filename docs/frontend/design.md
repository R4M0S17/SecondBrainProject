# Cerebro — Frontend Design Specification
## Tauri 2.0 + React 18 + TypeScript + Tailwind CSS

> **Status:** Design document — no frontend code exists yet. All backend API contracts are implemented and live at `http://localhost:7842`.

---

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Desktop shell | Tauri 2.0 (Rust) |
| UI framework | React 18 + TypeScript |
| Styling | Tailwind CSS v3 |
| State management | Zustand (lightweight, no boilerplate) |
| HTTP client | `fetch` via a thin `api.ts` wrapper |
| Icons | Lucide React |
| Build | Vite |

**Folder layout (inside `ui/tray/`):**

```
ui/tray/
  src/
    api/
      client.ts        # typed fetch wrappers for all endpoints
      types.ts         # TypeScript mirrors of Pydantic models
    components/
      chat/            # ChatWindow, MessageBubble, SourcesPanel, ToolHistory, MemoryPanel
      status/          # StatusBar, OllamaIndicator, RamGauge
      settings/        # SettingsPanel, FolderPicker, ModelSelector, ToolToggles
      wizard/          # WizardShell, StepOllama, StepModel, StepFolders
      shared/          # ConfirmModal, Toast, Spinner, Badge
    stores/
      chat.ts          # conversation history, active agent, streaming state
      system.ts        # /status polling (5s interval)
      settings.ts      # /config state with optimistic updates
    App.tsx
    main.tsx
  src-tauri/
    src/main.rs        # tray icon, global hotkey, window management
    tauri.conf.json
    resources/
      cerebro-backend  # PyInstaller bundle (generated by make package-backend)
```

## Application Shell

Cerebro lives in the **system tray**. The main window is a floating panel that appears on `Cmd+Shift+Space` (macOS) / `Ctrl+Shift+Space` (Windows/Linux) and dismisses by clicking outside or pressing `Escape`.

```
┌─────────────────────────────────────────────────────────┐
│  [Agent Selector ▼]   [Model Badge]       [⚙] [×]       │  ← Header bar
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Conversation area (scrollable)                         │  ← Main content
│                                                         │
├─────────────────────────────────────────────────────────┤
│  [Input box                              ] [Send ↵]     │  ← Input area
├─────────────────────────────────────────────────────────┤
│  ● Ollama OK  phi3:mini  142 files  RAM 3.8/8GB  p95 8s │  ← Status bar
└─────────────────────────────────────────────────────────┘
```

Window dimensions: **560 × 680 px** (resizable, minimum 400 × 480).

## Screen 1 — Onboarding Wizard

Shown on first launch (backend `GET /wizard/status` returns `is_first_launch: true`). Replaces the main window until all three steps are complete.

```
┌─────────────────────────────────────────────────────────┐
│                    Welcome to Cerebro                   │
│              Your private AI second brain               │
│                                                         │
│  ●━━━━━━○────────○                                      │  ← Step indicator (3 dots)
│  Step 1 of 3: Start Ollama                              │
│                                                         │
│  Cerebro needs Ollama running locally.                  │
│  Download: https://ollama.ai                            │
│                                                         │
│  [Checking...]  /  ✓ Ollama is running                  │  ← Auto-polls every 2s
│                                                         │
│                                    [Continue →]         │
└─────────────────────────────────────────────────────────┘
```

**Step flow:**

| Step | Backend call | Success condition | UI action |
|------|-------------|-------------------|-----------|
| 1 — Check Ollama | `POST /wizard/step/ollama` | `{ok: true}` | Enable Continue |
| 2 — Pull models | `POST /wizard/step/model` | Returns 200 | Show progress log (streamed stdout), then Enable Continue |
| 3 — Select folders | `POST /wizard/step/folders` with `{paths: [...]}` | Returns 200 | Mark wizard done, open main chat window |

Step 2 (model pull) shows a scrolling log area with each `ollama pull` output line. This can take several minutes — show elapsed time and a cancel button that warns "Cancelling will leave models incomplete."

Step 3 uses a native folder picker dialog (Tauri `open()` dialog) plus a list of selected paths with remove buttons.

## Screen 2 — Main Chat Window

### Header

```
[General ▼]   phi3:mini · ollama   [⚙ Settings]  [×]
```

- **Agent Selector dropdown** — lists all agents from `GET /status → active_agent` plus known profiles. Options: General, Academic (`/academic`), Code (`/code`). Selecting an agent sets the prefix automatically.
- **Model badge** — `model · provider` from `/status`. Click opens Model Selector (see Settings).
- **Settings button** — opens the Settings Panel as a slide-over.

### Conversation Area

Messages render in a standard chat layout:
- User messages right-aligned, `bg-elevated` pill
- Assistant messages left-aligned, no background (flat)
- Each assistant message has a footer:

```
phi3:mini  ·  4.2s  ·  [📄 2 sources]  [🔧 1 tool]  [🧠 3 memory]
```

Clicking these badges toggles the respective detail panel inline below the message.

**Sources panel (inline, collapsible):**
```
📄 Sources used
  ├ ~/Documents/thesis.pdf  chunk 12  (score 0.91)
  └ ~/Notes/research.md     chunk 3   (score 0.84)
```

**Tool history panel (inline, collapsible):**
```
🔧 Tools called
  ├ search_documents  "LangGraph state machines"  → 3 results  (1.2s)
  └ read_file  ~/Notes/research.md  → 4KB read  (0.1s)
```

**Memory panel (inline, collapsible):**
```
🧠 Memory retrieved
  ├ Episode: "Thesis outline draft"  relevance 0.88
  └ Episode: "Graph theory notes"    relevance 0.71
```

**Loading state:** While waiting for a response, show a typing indicator (three pulsing dots) in the assistant message position. If `total_latency_ms` is expected to exceed ~3s (based on recent p95), also show "Thinking with phi3:mini…" as subtitle text.

**Warnings:** If `warnings` array is non-empty in the response metadata, show a small amber toast at the top of the window: "⚠ provider_fallback — switched to qwen2:1.5b".

### Input Area

```
┌──────────────────────────────────────────────────┐
│  Ask anything…  (Shift+Enter for newline)         │
└──────────────────────────────────────────────────┘  [↵ Send]
```

- Auto-focuses when the window opens.
- Pressing `/` at the start of an empty input shows an autocomplete for `/academic` and `/code` commands with descriptions.
- `Enter` sends, `Shift+Enter` adds newline, `Escape` closes window.
- When a request is in-flight, the input is disabled and Send becomes a Cancel button (cancels the fetch).

### Confirmation Modal

When a tool call returns `requires_user_confirmation: true` (from the PolicyEngine), execution pauses and a blocking modal appears:

```
┌───────────────────────────────────────┐
│  ⚠ Tool requires your approval        │
│                                       │
│  write_file                           │
│  Path: ~/Documents/summary.md         │
│  Action: Create new file (2.3 KB)     │
│                                       │
│  [Deny]              [Approve]        │
└───────────────────────────────────────┘
```

The user's approval/denial is sent back to the backend via `POST /query` with a confirmation payload (exact contract TBD during implementation — the Python backend `requires_user_confirmation` field is already in `PolicyResult`).

## Screen 3 — Settings Panel

Slide-over from the right, does not replace the chat window.

### Section: Watched Folders

```
Watched Folders
  ~/Documents        [×]
  ~/Projects/thesis  [×]
  [+ Add Folder]
```

Changes call `PUT /config` with the updated `ingestion.watched_paths` array. After saving, a `POST /index` is fired automatically with the new paths.

### Section: Index Progress

When `POST /index` is active, a progress section replaces the folder list temporarily:

```
Indexing…
  ████████████░░░░  68%   (312 / 458 files)
  Currently: ~/Documents/research/chapter4.pdf
```

The backend `/index` endpoint only returns `{status: "started", job_id}` today — the progress UI polls `GET /status → indexed_files` and compares against a snapshot taken before indexing started to estimate progress.

### Section: Model Selector

```
Active Model
  ● phi3:mini  (Ollama — available)  RAM: 3.8 GB / 8 GB
  ○ qwen2:1.5b (Ollama — available)  RAM: 1.2 GB

Embedding
  nomic-embed-text  (always fixed)
```

Changing the model calls `PUT /config` with `providers.default_chat`.

### Section: Agent Tools

```
Tool Permissions
  [✓] Execute Python    (sandboxed, 10s timeout)
  [✓] Write File        (requires confirmation)
  [ ] Execute Python    ← shown per-agent when agent is not "general"
```

Toggles call `PUT /config` with `tools.enable_execute_python` / `tools.enable_write_file`.

### Section: Do Not Disturb

```
[○] Do Not Disturb  — silences all proactive notifications
```

Calls `PUT /config` with `scheduler.do_not_disturb`.

## Status Bar

Always visible at the bottom. Polls `GET /status` every **5 seconds**.

```
● Ollama OK  ·  phi3:mini  ·  142 files  ·  RAM 3.8/8 GB  ·  p95 8.4s  ·  47 queries
```

- **Ollama indicator:** green dot if `ollama_ok`, red dot + "Ollama down" if false. Clicking it opens a toast with instructions to start Ollama.
- **File count:** `indexed_files` files. Clicking triggers a new `POST /index` with the current watched paths.
- **RAM gauge:** `ram_used_gb` / total. Amber if used > 4 GB, red if > 5.5 GB.
- **p95 latency:** from `p95_latency_ms`. Amber if > 12s, red if > 18s.

## API Client (`api/client.ts`)

```typescript
const BASE = "http://localhost:7842";

export async function query(question: string, agent: string): Promise<QueryResponse>
export async function getStatus(): Promise<StatusResponse>
export async function startIndex(paths: string[]): Promise<IndexResponse>
export async function getConfig(): Promise<Record<string, unknown>>
export async function updateConfig(patch: Record<string, unknown>): Promise<Record<string, unknown>>
export async function getWizardStatus(): Promise<WizardStatus>
export async function wizardStepOllama(): Promise<{ ok: boolean }>
export async function wizardStepModel(): Promise<void>
export async function wizardStepFolders(paths: string[]): Promise<void>
```

All functions throw a typed `ApiError` on non-2xx responses. The `query()` function accepts an optional `AbortSignal` for cancellation.

## Global State (`stores/`)

**`chat.ts`** (Zustand):
- `messages: Message[]` — full conversation history (not persisted across sessions)
- `activeAgent: "general" | "academic" | "code"`
- `isLoading: boolean`
- `pendingConfirmation: ToolConfirmationRequest | null`

**`system.ts`** (Zustand, auto-refreshes every 5s):
- `status: StatusResponse | null`
- `isOllamaOk: boolean`
- `lastRefreshed: Date`

**`settings.ts`** (Zustand, synced with backend):
- `config: Record<string, unknown>`
- `isDirty: boolean` (optimistic updates before `PUT /config` settles)

---

## Tauri Main Process (`src-tauri/src/main.rs`)

Responsibilities:
1. Register global hotkey `Cmd+Shift+Space` / `Ctrl+Shift+Space` — toggle the main window visibility.
2. Show a tray icon (simple brain icon). Right-click menu: Show / Settings / Quit.
3. On first launch: spawn the Python backend (`cerebro-backend` from `resources/`) as a child process.
4. On app exit: kill the Python backend process.
5. Auto-update via Tauri's built-in updater pointing to GitHub Releases.

The window is `decorations: false` (frameless) and `alwaysOnTop: true` while focused. It blurs (hides) when focus is lost.

---

## Implementation Order

1. `src-tauri` scaffolding + tray icon + hotkey + backend process spawn
2. `api/client.ts` + `api/types.ts` (typed wrappers, no UI yet)
3. Onboarding Wizard (unblocks local testing)
4. Status Bar (polls `/status`, validates backend connection)
5. Chat Window — input + plain text responses
6. Chat Window — metadata badges + Sources/Tool/Memory panels
7. Settings Panel — folder management + model selector
8. Confirmation Modal
9. Polish: animations, keyboard nav, accessibility labels
